# smartrecall

Приложение для интервального повторения (карточки), которое предсказывает
индивидуальный "период забывания" пользователя вместо жёсткого алгоритма
SM-2 (как в Anki).

## Идея

Классические алгоритмы (SM-2 и его вариации) используют фиксированные
эвристики для расчёта интервала повторения. `smartrecall` вместо этого
обучает модель на реальных данных о попытках вспоминания, чтобы предсказывать
вероятность вспомнить карточку в момент времени `t` и подбирать интервал
индивидуально — под конкретную карточку и конкретного пользователя.

## Стек

- **ML/DS** — pandas, scikit-learn / LightGBM, Jupyter. Модель: Half-Life
  Regression (экспоненциальная модель забывания + логистическая/линейная
  регрессия) на [Duolingo Spaced Repetition Dataset](https://github.com/duolingo/halflife-regression)
  (~13 млн строк).
- **Backend** — FastAPI, эндпоинт `/predict_interval`. Модель подгружается
  при старте, без тяжёлой инфраструктуры.
- **Mobile** — Flutter, локальная БД (Hive/SQLite) для офлайн-режима,
  синхронизация с backend.

## Структура репозитория

```
ml/         обучение модели: ноутбуки, feature engineering, экспорт модели
backend/    FastAPI-сервис с эндпоинтом /predict_interval
mobile/     Flutter-приложение (карточки, офлайн-режим)
docs/       вспомогательная документация
```

## План

### Этап 1 — ML (1-2 недели)
- Скачать датасет, взять сэмпл для итераций
- EDA, feature engineering (сложность карточки, история попыток, интервал)
- Обучить модель, сравнить с baseline SM-2 (метрика: MAE по recall probability)
- Обучить финальную модель на полном датасете

### Этап 2 — Backend (3-5 дней)
- FastAPI, эндпоинт `/predict_interval`
- Простое хранение (SQLite/PostgreSQL)
- Локальный запуск, без cron на старте

### Этап 3 — Flutter (1-2 недели)
- UI карточек, локальное хранение
- Интеграция с API
- Офлайн-режим + синхронизация

### Этап 4 — Доработка
- Персонализация под конкретного пользователя (дообучение на его данных)
- Метрики использования, улучшение UX
